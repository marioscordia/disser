## **1. Introduction** 

The number of multilingual documents is increasing rapidly. Due to global connectivity, we are communicating and collaborating with people from all around the globe. Because of that, we are required to prepare documents and resources in the language the target audience will be able to understand; when the audience are locals, one could prepare the resource in their local language. But when presenting to a more general audience, for instance at a global conference, the resource is usually prepared in a more spoken language. Thus, the topic is presented in different languages. This especially applies to education and law; In education, a topic is described, adapted, translated, and published in various languages, which can be seen in the massive amounts of courses and textbooks that are available. In law, legislation and treaties are translated in the languages of countries the documents are relevant to, making them accessible to their lawyers and decision makers. Because of the huge amount of multilingual documents, one requires an effective solution to search through them.

## _1.1. Research objectives and contributions_ 

The main aim of this work is to develop a cross-lingual document retrieval model that is able to both calculate the document’s relevancy to the query with high precision, and provide insight into why a document is relevant. 

The main research objectives are to (1) evaluate the model’s performance on data sets consisting of queries and documents in different languages (language pair data sets), where the languages have various degrees of similarity, (2) assess the degree of document score interpretability the model provides, and (3) analyze the impact the objective loss function used during training has on the performance of cross-lingual document retrieval models. 

We propose a learning-to-rank model named LM-EMD which uses multilingual BERT to generate token vector representations and Earth Mover’s Distance (EMD) to measure the document’s relevancy to the query, and provide interpretable view into why a document is relevant. 

The model is evaluated on five language pairs, three of which are high-resource, and two are low-resource languages, using the Precision at 1 (P@1) and Mean Average Precision (MAP) metrics. The results show the proposed model performs similar as the selected comparing models on high-resource languages, but its performance decreases on low-resources languages. 

We also perform an analysis on how the selection of the objective loss function used during training effects the performance of the document retrieval models. We compare two commonly used loss functions, cross-entropy and pairwise ranking, and find that training the models using pairwise ranking yields better performance. 

The contributions of this paper are: 

- the theoretical background of using optimal transport for measuring document relevancy, 

- a supervised multilingual learning-to-rank model which outputs interpretable relevance scores, 

- a comparison of the model’s performance fine-tuned using two loss functions, cross-entropy and pairwise ranking, commonly used for training document retrieval models that employ language models.

## **2. Related work** 

_General information retrieval._ The objective of an efficient Information Retrieval (IR) method is to retrieve documents that are relevant to the user’s query. To improve its performance, various methods are employed. Relevance feedback is a feature of an IR system which gathers user’s feedback to improve the system’s performance. With the emergence of neural information retrieval models, neural relevance feedback approaches were also developed [1]. Query expansion is a technique which extends the query by adding values to improve document retrieval. The added values are usually similar or related to those in the query, and can be assigned from knowledge bases [2,3], ontologies [4], 

or by using word embeddings [5]. An extensive survey of query expansion techniques is found in [6]. In addition to developing an effective model for finding relevant documents, research on other aspects, such as fairness of the retrieved documents [7], and the experiment reproducibility on neural information retrieval models [8], has been done in the last years. 

Prior work is different from the proposed model in the following ways: (1) our model does not use relevance feedback or query expansion, but uses the raw query text when calculating the document’s relevance; (2) while prior work is evaluated on monolingual data sets, our method is designed for cross-lingual document retrieval, i.e. where the query and document are in different languages; (3) our method does not use knowledge bases or ontologies to retrieve similar or related tokens, but a multilingual language model that returns contextual embeddings of the query’s and document’s tokens. These are then used to measure their semantic similarity. 

_Cross-lingual information retrieval (CLIR)._ In order to retrieve documents that are in various languages, one must bridge the lexical gap between them. Because of this gap, traditional information retrieval models need to be accompanied with methods that are able to transfer the documents and queries into the same or similar semantic space. The most common are: machine translation systems, word embeddings, and transformer language models. 

Machine Translation systems (MT) are used to translate either the query or documents [9]. They require huge amounts of parallel data to train the models where such resources are scarce for many language pairs. If needed, it is possible to employ MT services from different providers, such as Google Translate,[1] DeepL,[2] and Translate.com,[3] but can be expensive when the data set is huge. 

Word embeddings are used to generate query and document vector representations in the same semantic space. In recent years, various word embedding methods were proposed [10–13]. While most of them are trained on single language data sets, unsupervised approaches for aligning embeddings in a common vector space were explored [14–20]. The aligned word embeddings are then used to either (1) translate the query into the target languages and use traditional IR methods to find relevant documents, or (2) create a vector representation of both the query and document and calculate the cosine distance of the two vectors [21]. However, word embeddings assign the same vector to a word regardless of its meaning. This can make documents seem close in the semantic space, even though the meaning of their shared words are different. 

Language models are used to generate query and document vector representations. The majority of research is on modifying BERT [22] for monolingual information retrieval [23–29]. These models measure the document’s relevance by concatenating the query and document text, i.e. constructing the input in the form of [CLS] query [SEP] document [SEP], sending it through the model, and using the representation of the [CLS] token to predict the document’s relevance. This approach enables sharing of the query and document contexts with each other, but is also expensive to compute since it has to be done for every query and document. An alternative approach was presented [30] where the query and document representations are constructed separately by pooling or aggregating the language model’s output. One can then create the document representations ahead of time and generate only the query vectors at run-time. Multilingual language

_Earth Mover’s Distance (EMD)._ EMD, also known as the 1- Wasserstein distance [35,36], is a metric that measures the similarity between two distributions. It was widely adopted in image processing and retrieval [37–39]. However, it also has applications in natural language processing and text retrieval tasks.

## **3. Measuring document relevancy with optimal transport** 

In this section, we present the theory used to measure the document’s relevance to the query. First, we provide an overview of the optimal transport theory. Next, we describe how the queries and documents are represented, and how optimal transport is used to measure the document’s relevance.

## **4. Model architecture** 

Using the theory presented in Section 3, we propose a learning-to-rank model that generates interpretable document relevance scores. It consists of two components: (1) a multilingual language model used to extract the query and document token representations, and (2) the EMD to calculate the document relevance scores. As shown in Section 4.3, the EMD solution can also be used to interpret why the document is relevant. 

The model’s architecture and data flow is depicted in Fig. 1. While this section focuses on the model’s architecture, its technical implementation is found in Section 5.4. 

## _4.1. Query and document representation_ 

Language models generate contextual embeddings, i.e. representations that change based on the token’s context. The language model first splits the input text into subword segments (known as tokens) by using the model’s associated tokenizer, a subword segmentation algorithm that converts the input text into character n-grams. Afterwards, the model generates a vector representation for each token (known as an embedding) based on the token’s context. These embeddings capture the token’s semantic meaning. Therefore, tokens with similar or related meaning are found in similar contexts, hence their corresponding embeddings are closer in the embedding space. This can be extended to other languages by using multilingual language models, such as multilingual BERT [31], XLM [32], and XLM-RoBERTa [33]. 

Let _q_ and _d_ be the query and document, respectively. Using a language model we extract the query’s and document’s tokens and their embeddings. Because the model has a length limit for its input, we split longer documents into parts such that each part has at most the maximum length the model can process, and afterwards concatenate the model’s outputs. 

The tokens and their embeddings are then grouped together to create the query and document representation sets _Tq, Td_ consisting of (token, embedding) pairs used for measuring the document’s relevance score (see Section 4.2):

The entries of _P_ show how much ‘‘mass’’ is transported between the query and document token distributions. For instance, the entry _Pi,j_ shows the amount of ‘‘mass’’ that is moved between query token _qi_ and document token _dj_ ; the smaller the entry’s value, the smaller the ‘‘mass’’ moved between the tokens. In order to reach the minimum of the optimal transport problem, the matrix _P_ must have larger values at entries associated with the tokens that are closer in the embedding space (the entry _Pi,j_ must be large when the distance _Di,j_ is small), otherwise it would transport ‘‘mass’’ between tokens that are further apart (have a higher move cost) and thus the matrix could not be the solution of the optimization problem. Furthermore, the larger the number of query and document tokens that are close in the embedding space, the smaller the EMD score — making the document more relevant to the query. 

To view which document tokens have the largest significance on the relevance score, we must only read the values of the transportation matrix. Fig. 3 shows an illustrative example of how to interpret the token importance looking at the distance matrix and transportation matrix. The distance matrix contains various degrees of similarity between the tokens. The majority are distant but there are a few that are close, e.g. the token pair ( _q_ 4 _, d_ 5) exhibit strong similarity. This is then reflected in the transportation matrix which indicates a strong match between the pair, hence the token _d_ 5 is significant for the document’s relevance. Similarly, we find that ( _q_ 3 _, d_ 4) also have a strong match. While the ( _q_ 1 _, d_ 7) and ( _q_ 2 _, d_ 8) pairs have a medium match, the remainder have only a weak match. Hence, we conclude that the document is relevant because its tokens _d_ 4, _d_ 5, _d_ 7 and _d_ 8 have a significant similarity to the query tokens.

## _5.4. Implementation details_ 

In this section, we present the details of how is the LM-EMD model developed. It is implemented using PyTorch [55] and its source code is available on GitHub [56]. 

_Language model._ The model uses the pre-trained multilingual BERT, more precisely the bert-base-multilingual-cased model,[5] available via the HuggingFace’s transformer library [57]. The language model consists of 110M parameters and was pretrained on the top 104 languages with the largest Wikipedia using the masked language modeling objective. The multilingual BERT uses the WordPiece tokenizer [58], which adds special word boundary symbols such that the original word sequence can be retrieved from the wordpieces sequence without ambiguity. 

_Similarity measure._ The Earth Mover’s Distance is calculated using the Sinkhorn-Knopp algorithm [44], an iterative algorithm for solving regularized EMD. The algorithm requires two hyperparameters: (1) the number of iterations _nit_ , and (2) the regularization factor _γ_ . The regularization factor is used to regulate the size of the regularization term and thus the precision of the final EMD optimization solution. Smaller factors provide more precise solutions, but they also introduces a higher risk of underor over-flowing gradient values. 

In order to provide the Sinkhorn-Knopp algorithm enough iterations to converge to a solution, we set _nit_ = 500. To analyze the impact of the regularization factor on the model’s performance, we train three models using _γ_ = {0 _._ 1 _,_ 1 _,_ 10}, respectively. These values are frequently used with the algorithm in other related works [59]. 

_Model fine-tuning._ The LM-EMD model parameters are updated using the AdamW optimizer [60] with the initial learning rate = 10[−][6] , epsilon = 10[−][6] , and weight decay = 0.01. These hyperparameters were selected using grid search and monitoring the loss values of the first 1000 examples from the EN → DE training data set. 

The model fine-tuning is performed on the selected language pair training sets for 1 epoch. We employ gradient accumulation and update the model after every 16th mini-batch, where a mini-batch consists of the query and its 40 relevant and irrelevant documents. We use one of the two loss functions: (1) cross-entropy, and (2) pairwise ranking loss function, defined as

⃗where _Td_ is the set of the unique terms in document _d_ , and _wt_ and _xt_ are the weight and word embedding associated with the term _t_ , respectively. ## _6.1. Interpretability_ 

This section describes how the LM-EMD model scores can be interpreted. We show that the document’s relevance is associated with the number and intensity of the matches between the query’s and document’s tokens. In addition, the relevance can be described graphically. 

We prepared the query ‘‘Who was the first president of the United States?’’ and five documents in German: one contains the answer (George Washington), one is similar but incorrect 

(Abraham Lincoln), and three irrelevant documents with various degrees of similarity. Using the LM-EMD model we calculate all document relevance scores with respect to the query. The scores are shown in Table 3. 

The model correctly detected that George Washington is the most relevant document, followed by Abraham Lincoln. To identify which tokens contributed the most to their respective score, we follow the interpretation described in Section 4.3, and generate the graphs of the distance matrix and transportation matrix values for each document (similar to Fig. 3). The graphs are shown in Fig. 4. 

Looking the George Washington graphs (first row), we find that almost all query tokens have a strong match with those in the document. Most are literal translations (e.g. ‘‘president’’, ‘‘Präsident’’), but some are matched due to their semantic relatedness, such as the query word ‘‘Who’’ and document words ‘‘George Washington’’. 

The Abraham Lincoln graphs (second row) show that only half of the query tokens have a strong match. This is due the smaller number of close tokens as seen in the distance matrix. Because of this, the document got a worse relevance score than the George Washington sentence. 

In comparison, the third set of graphs belongs to the Christopher Columbus document, which is an irrelevant document. The graphs show the model finds a strong match only for the literal translation of ‘‘first’’, and some conjunction words, such as ‘‘was’’, ‘‘the’’, and ‘‘of’’. Surprisingly, it also finds a weak match between the words ‘‘president’’ and ‘‘Vizekönig’’ (en. viceroy), which are positions of power, and between ‘‘United States’’ and ‘‘Kolumbus’’.[6] This shows that the model is able to detect the slightest relations between the cross-lingual tokens. Nevertheless, the document has a small number of matches and thus has a smaller relevance score. 

As seen in the example, the document’s relevance is associated with the number of strong matches between the query’s and document’s tokens; the greater the number and the stronger the match between the tokens, the greater the relevance. Because of this, the LM-EMD model generates interpretable relevance scores which are supported by the graphic visualizations as shown in this section.

## **7. Discussion** 

In this section, we discuss the experiment’s results. We highlight the model’s strong and weak points, as well as its theoretical and practical implications. 

_Model performance._ The proposed LM-EMD model shows comparable performance with the best performing comparing model BERT-CLS on the high-resource languages with an average 96.8% P@1 and 98.1% MAP score. However, LM-EMDs performance is significantly lower than of BERT-CLS on low-resource languages, with an average 84.6% P@1 and 90.3% MAP compared to the average 88.2% P@1 and 93.0% MAP achieved by BERT-CLS. 

When comparing LM-EMD to BERT-MAX and BERT-MEAN, both using all of the token embeddings to measure the document’s relevance to the given query, the LM-EMD outperforms the other two models across all language pairs. This shows that EMD is a superior measure as it takes all of the token distances into account when assigning the relevance score. This is also reflected when comparing WE-based methods where WE-EMD has the best performance scores. 

_Interpretability._ Unlike the cosine distance, EMD can be used to generate interpretable relevance scores. The EMD solution outputs the transportation matrix which indicates which querydocument token pairs are semantically similar and thus improve the relevance score. The similarity it detects ranges from distant connections to synonyms and literal translations. However, EMD is more computationally expensive than cosine distance as it needs to run the Sinkhorn-Knopp algorithm to get the final score. 

## **8. Conclusion and future work** 

We propose a new LM-EMD model used for cross-lingual document retrieval. It generates outputs that both measure the document’s relevancy with high precision and provide insight into why the document is relevant. It is compared to other word embedding and multilingual language model approaches showing it has similar performance as the best performing compared model on high-resource languages. We provide the explanation of how to interpret the model’s outputs and show its capabilities on an example with an English query and German documents. An analysis of the impact an objective loss function has on training and fine-tuning CLIR models has shown that there is a significant increase in performance when using the pairwise ranking instead of the cross-entropy loss function. The code for reproducing the experiments is open source [56]. 

In the future, we intend to make the model smaller by using model distillation and pruning, which will potentially speed up the calculation of the relevance scores. Moreover we plan to integrate various text features, such as part-of-speech tags, into EMD calculation, replace EMD with _p_ -Wasserstein distance where _p_ ≥ 2, and run the experiments using other multilingual language models. We believe this will increase the understanding of the usability of the proposed approach and potentially find new directions of how to make explainable models for (cross-lingual) document retrieval.
